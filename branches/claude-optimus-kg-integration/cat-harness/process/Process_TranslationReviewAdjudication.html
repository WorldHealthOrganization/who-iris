nameTranslation review and adjudication
summaryA person's word on a translation, carried from the page they read it on to the record.
descriptionA person's word on a translation, carried from the page they read it on to the record. Candidate translations come from any engine and from anyone; a reader opens the review page or a block's 🌐 pane, accepts what is there, or picks a ranked candidate or writes their own; that travels as a GitHub issue; a workflow checks it and opens a pull request; a maintainer merges it. You are in this process when a catalogue has a translation nobody has adjudicated: a machine, flagged or stale cell on the review page, or a string a block's 🌐 pane shows as proposed, agent, mt, missing or stale. translation-workflow produces the machine translation and human-translation-workflow makes a locale official; this process sits between them and does neither. What it records is that ONE catalogue was read by ONE person who could be held to it, against the exact bytes they saw. Two rules hold throughout. Candidates are never a barrier to having a translation: an empty msgstr gets the first candidate, marked fuzzy, so the page always has something to show. And a reader's text is a proposal until a collaborator chooses it: anyone may propose, and every proposal is appended to the candidates sidecar beside the others; only an owner, member or collaborator adjudicates, by choosing one text as the translation with a reason. A string nobody has adjudicated shows the best-ranked candidate, fuzzy and unofficial, unless an official source's English matches the msgid exactly. Locale sign-off (X-Folio-Official, the locale's status.json) is a separate, deliberate act that this process never performs. GitHub is one Tool here, not the process: the issue is the carrier of the verdict and the pull request the carrier of the record. Another forge carrying the same translation-adjudication/v1 record would be another Tool satisfying the same skill.

  • owner-decision 2026-11-18 https://github.com/litlfred/cat-harness-tools/pull/2432
    Owner rulings, 2026-11-18, on per-block translation feedback: (1) a 🌐 pane on every page, source-language pages included, listing every locale's current translation, its status, chosen.how and chosen.by, the page's own locale first and the others collapsed; (2) proposals live in the translation-candidates/v1 sidecar, and any GitHub author's proposal is appended as a human candidate; (3) only an owner, member or collaborator adjudicates, everyone else proposes; (4) the auto-pick ranks official 0, adjudicated 1, human 2, translation platform 3, agent 4, machine translation 5, a QA failure adds 10, a stale candidate is never auto-picked, ties go to the newest; (5) an auto-pick is official only on an exact sourceText match. Hence Task_TRA_BlockPane, Task_TRA_Propose, Task_TRA_AutoPick and End_TRA_Adjudicated. The implementation is cat-harness-tools#2432.
